## Album Repository

`com.example.MusicBoxd.Repository.AlbumRepository` is the Spring Data
repository for the `Album` entity:

```java
public interface AlbumRepository extends CrudRepository<Album, Long> {
}
```

### What it provides

`AlbumRepository` declares no custom query methods of its own — it exposes
exactly the standard `CrudRepository<Album, Long>` operations, the most
relevant of which are:

- `save(Album album)` — insert a new album (or update an existing one if its
  `id` is already set). On insert, the `id` is generated by the database.
- `findById(Long id)` — returns an `Optional<Album>`.
- `findAll()` — returns every album in the table.
- `deleteById(Long id)` — removes an album by id.
- `existsById(Long id)`, `count()`, and the other inherited `CrudRepository`
  methods.

### How to use it

```java
@Autowired
private AlbumRepository albumRepository;

Album album = new Album("ext-1", artist.getId(), "Kid A", (short) 2000,
        "http://art.example/kid-a.png");
Album saved = albumRepository.save(album);

Optional<Album> found = albumRepository.findById(saved.getId());
```

### When to use it

Use `AlbumRepository` wherever the application needs to create, look up,
list, or remove album records — for example, when importing an artist's
discography, or when rendering an album detail page.

### Notes / limitations

- Because `Album.artistId` is a plain column and not a JPA relation,
  fetching an `Album` via this repository does not fetch its `Artist`;
  callers must query `ArtistRepository` separately if they need the related
  artist. The same applies in reverse for an album's songs, reviews, and
  comments — those live in their own repositories, keyed by `albumId`.
- There is no method to look up albums by `artistId`, `externalId`, or
  `title` yet — if that's needed, add a derived query method such as
  `List<Album> findByArtistId(Long artistId)`.
