## Song Repository

`com.example.MusicBoxd.Repository.SongRepository` is the Spring Data
repository for the `Song` entity:

```java
public interface SongRepository extends CrudRepository<Song, Long> {
}
```

### What it provides

`SongRepository` declares no custom query methods of its own — it exposes
exactly the standard `CrudRepository<Song, Long>` operations, the most
relevant of which are:

- `save(Song song)` — insert a new song (or update an existing one if its
  `id` is already set). On insert, the `id` is generated by the database.
- `findById(Long id)` — returns an `Optional<Song>`.
- `findAll()` — returns every song in the table, regardless of album.
- `deleteById(Long id)` — removes a song by id.
- `existsById(Long id)`, `count()`, and the other inherited `CrudRepository`
  methods.

### How to use it

```java
@Autowired
private SongRepository songRepository;

Song song = new Song("ext-1", album.getId(), "Idioteque", 8,
        "http://songs.example/idioteque", "http://art.example/idioteque.png");
Song saved = songRepository.save(song);

Optional<Song> found = songRepository.findById(saved.getId());
```

### When to use it

Use `SongRepository` wherever the application needs to create, look up,
list, or remove song records — for example, when importing an album's
tracklist, or when rendering a song/track detail view.

### Notes / limitations

- Because `Song.albumId` is a plain column and not a JPA relation, fetching a
  `Song` via this repository does not fetch its `Album`; callers must query
  `AlbumRepository` separately if they need the related album.
- There is no method to look up songs by `albumId` yet — if that's needed,
  add a derived query method such as `List<Song> findByAlbumId(Long albumId)`.
